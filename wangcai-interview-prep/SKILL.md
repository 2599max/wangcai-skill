# 面试预测（wangcai-interview-prep）

基于简历内容预测面试问题并准备回答要点。回答素材只来自简历事实，不替用户编故事。简历里由 ASu 标准标注的 `[~X%]`/`[需核实]` 条目是面试高危点，必须进风险预警。

## 工作流

1. **通读简历，按模块列「必问锚点」**：最近一段经历、最大的项目、时间线空窗、职级跳跃、高频技术词、简历里出现的每个量化指标（面试官最爱追问数字来源）。
2. **生成 6-8 个问题**，覆盖四类：
   - 深挖类：项目细节、技术选型原因（为什么 Redis 集群不是单机）、你具体负责的边界（旺财原则：Owner / 0→1 / Scope 必须答得清）；
   - 挑刺类：指标来源（「提升 40% 怎么测的？」）、失败与复盘、为什么离职；
   - 场景类：给你一个新需求/线上事故怎么处理；
   - 匹配类：结合目标岗位（若有 JD）问「你的经验如何迁移」。
3. **每个问题输出五件套**：
   - 问题本身；
   - 追问树：2 层追问（第一层问细节，第二层问反例/极端情况），呈树状列出；
   - 考察意图（面试官在筛什么：真实性/深度/协作/抗压）；
   - 回答要点（STAR 结构的提纲，30 秒能讲完；成果行与简历 XYZ 口径一致，避免答出简历上没有的数字）；
   - 需要提前准备的数据/材料（如「当时的监控截图」「需求文档要点」「PR 链接」）。
4. **风险预警清单**：简历里 `[需核实]` 的估算、`[~X%]` 估算、时间线 gap、职级跳跃——每条给一个「诚实框架」的说法模板（承认 + 边界 + 学习路径）。

## 输出格式

按「必问题（3）+ 高概率题（3-5）+ 风险预警清单」组织；每个问题独立成块，方便用户逐条演练。

## 红线

- 回答要点是提纲不是台词，鼓励用户用自己的话讲。
- 不建议隐瞒或美化事实；空窗与失败给「诚实框架」模板。
- 回答口径不得超出简历事实；用户答不出简历上的数字时，建议先回 wangcai-resume-polish 把该数字改成可核验的表述。
