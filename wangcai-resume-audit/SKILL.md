# 简历体检（wangcai-resume-audit）

对一份简历做全面体检，输出可执行的修改清单。规则与「旺财简历」编辑器内置体检引擎（弱动词表、联系方式校验、行长检查）对齐，内容质量基准对齐 [../references/asu-writing-standard.md](../references/asu-writing-standard.md)（ASu 金标准：四段式条目骨架 + XYZ 成果行 + 技术栈分层），并叠加证据式真实性审计。

## 输入

- 编辑器导出的简历 JSON / 简历文本 / 用户粘贴的简历内容。
- 若用户提供了晋升材料、项目文档等佐证，一并读取用于核验。

## 体检维度（输出评分表：维度 | 得分/10 | 主要问题）

### 1. 完整性
- 基本信息：姓名、手机（11 位）、邮箱（格式正确）、城市是否齐全。
- 教育：学校（官方名称）、专业、学历、起止时间。
- 工作/项目：每段有公司/项目名、职位、起止时间、≥2 行内容。
- 技能标签是否为空、是否有求职意向（目标岗位）；技术岗是否有 GitHub/作品链接。

### 2. 表达（对齐 ASu 金标准，逐条过）
- **四段式完整度**：「背景与目标 → 我的职责 → 技术实现 → 产出与保障」是否齐全；缺失段落指出并说明该段承载什么信息。
- **三要素可答性**：每段经历问三个问题——谁是 Owner？0→1 还是 1→100？Scope 多大（人数/流量/营收）？答不上来的标 `三要素缺失`。
- **XYZ 成果行检查**：实现类/产出类每行是否「达成 X·以 Y 度量·通过 Z」齐全；缺 Y 的行按「钱/时间/质量/规模」四问给量化方向。
- **边界清晰度**：个人贡献是否只写本人实际完成的部分；宣称 Owner 但描述为参与者要标出。
- **弱动词开头**：逐行扫「负责 / 参与 / 协助 / 配合 / 完成」，替换建议见金标准第五节。
- **行长度**：单行 >80 字符提示拆行（编辑器会触发体检警告）。

### 3. 结构 / ATS
- 模块顺序是否合理（应届教育前置；时间倒序；荣誉证书在后）。
- 时间线是否连续（gaps > 6 个月提示）。
- 是否存在大段散文（HR 10 秒 F 型扫描抓不到重点）；行首标签词是否全文统一。
- 技能标签是否分层（语言→框架→数据库→工具链）、熟练度是否与项目互相印证；是否堆砌 10+ 技术。
- ATS 硬规则：关键内容是否被表格/图片承载；缩写是否首次出现写全称。

### 4. 真实性核验（证据式）
把履历拆成**原子主张**逐条核验，每条标注：`✓ 有佐证` / `? 需核实` / `✗ 与材料冲突`：
- 学校/学位查官方名称与学制。
- 在职时间 vs 项目周期是否自洽；头衔 vs 职责范围是否匹配。
- 指标可信度：比例是否异常（如「性能提升 300%」要求给出测法）；`[~X%]` 估算是否已提醒核实。
- 无法核实的指标一律建议标注 `[需核实]` 或降级表述。

## 输出格式

1. 四维评分表（维度 | 得分/10 | 主要问题）。
2. **Top 5 问题**（按优先级）：问题 → 为什么影响求职 → 修改前 → 修改后（修改后优先按 ASu 四段式重排、成果行补 XYZ）。
3. 真实性核验清单（原子主张表）。
4. 一句话总评 + 下一步行动（改表达 → wangcai-resume-polish；改完导出/生成深链 → wangcai-resume-maker）。

## 红线

- 只标记问题与给建议，不直接改写事实；改写用 wangcai-resume-polish。
- 核验结论必须区分「证据不足」与「确认造假」，不得指控。
- 「真实性核验」框定为「面试官也会这么问，提前核验」，不是不信任用户。
