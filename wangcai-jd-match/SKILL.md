# JD 精准匹配（wangcai-jd-match）

把简历重写到对方招聘痛点上，每一句话都踩 JD 关键词，但不编造经历。

## 工作流

1. **拆解 JD**：从岗位描述提取三类要素——
   - 硬技能关键词（工具/技术/方法论，优先对齐 [references/skill-lexicon.md](references/skill-lexicon.md) 的词库分类：互联网技术 / 金融 / 运营 / 设计 / 通用职场）；
   - 软性能力要求（沟通、跨部门协作…）；
   - 隐性偏好（学历、年限、行业背景、稳定性的字里行间）。
2. **覆盖度映射**：逐条 JD 要求 × 简历经历，输出三列清单——
   - `已覆盖`：简历中有直接对应经历；
   - `弱覆盖`：做过但表述没踩到 JD 用词；
   - `未覆盖`：简历中无对应经历。
3. **重写**：
   - `已覆盖` 条目用 JD 的行业内部术语重写（对方写「包容性设计」就不写「无障碍优化」），保留真实事实与数字；
   - `弱覆盖` 条目调整措辞与顺序，把相关成果前置；
   - `未覆盖` 只在「补充建议」里给学习/项目路径，**不写入简历**。
4. **关键词落位**：命中的硬技能建议同步写入技能标签（编辑器 `skills.content`），按「精通 / 熟练 / 了解」分级。
5. **输出差距报告**：覆盖度统计（如 12/18 = 67%）+ 最大 3 个缺口 + 一周内可补的速赢项。

## 输出格式

1. JD 要素提取表（关键词 | 类别 | 简历覆盖状态）。
2. 逐条重写对照（原文 → JD 化改写，标注命中的关键词）。
3. 缺口与补充建议（含可量化的速赢行动）。
4. 技能标签增补清单。

## 红线

- 不编造没有的经历、项目、数据；未覆盖就是未覆盖。
- 重写只换表述与用词，不改事实（时间、公司、指标不动）。
